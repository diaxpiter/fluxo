# Design System Master File

> **LOGIC:** When building a specific page, first check `design-system/fluxo/pages/[page-name].md`.
> If that file exists, its rules **override** this Master file.
> If not, strictly follow the rules below.

**Project:** fluxo — personal finance flow-control app
**References:** Notion, Spotify, Vercel, Obsidian
**Mode:** Dark only (no light mode for now — not requested, and a half-supported second theme is worse than one polished theme)

This file was generated by the `ui-ux-pro-max` skill's `--design-system` search and then **hand-edited**: the raw auto-match skewed toward a marketing landing-page pattern (Exaggerated Minimalism / oversized hero type), Fira Code/Fira Sans, and a slate+blue corporate-fintech palette. None of that fits an actual dashboard app styled after Notion/Vercel/Spotify, so the real decisions below deviate from that raw output. Read this file, not the skill's raw suggestion, when extending the UI.

## Why these deviations

- **No blue "primary" color.** Vercel and Spotify barely use color at all outside of meaning — buttons are black/white, color is reserved for semantics. Here that means: neutral chrome everywhere, emerald = money in / brand accent, red = money out / destructive. Adding a third competing hue (the tool's default blue) would look more "generic SaaS template" than Notion/Vercel actually look.
- **Geist, not Fira Code/Fira Sans.** This project already ships Geist Sans + Geist Mono via `next/font/google` from the create-next-app scaffold — Geist *is* Vercel's real production typeface, a better match for the "Vercel" reference than anything in the font database. Numbers/amounts use Geist Mono (`font-mono tabular-nums`) for that precise, data-dense dashboard feel; everything else uses Geist Sans.
- **Dashboard layout, not the "Minimal Single Column" landing pattern.** That pattern (hero headline → bullets → CTA) is for marketing pages. This is an authenticated app; layout follows normal dashboard conventions instead.

## Color tokens

Defined as CSS variables in `src/app/globals.css` plus Tailwind's built-in `emerald`/`red` scales — no new hex values to maintain beyond the two below.

| Role | Value | Notes |
|------|-------|-------|
| `--background` | `#0a0a0a` | Near-black, not pure `#000` (avoids OLED smear / harsh contrast) |
| `--foreground` | `#ededed` | Off-white body text |
| Card / surface | `bg-foreground/[0.04]` | Elevated layer over background. The old `/[0.02]` was nearly invisible against the bg — this was the single biggest source of the "crude/flat" look |
| Card hover / input bg | `bg-foreground/[0.03]` idle → `/[0.05]` on focus | |
| Border | `border-foreground/10`, brightens to `/25–30` on focus/hover | Hairline, never a solid opaque gray |
| Positive / income / brand accent | Tailwind `emerald-500` (text/borders), `emerald-400` on colored chips | Doubles as the one brand accent color, à la Spotify's green |
| Negative / expense / destructive | Tailwind `red-400` (text), `red-500` (borders/chips) | `red-400` reads softer on dark bg than `red-500`, closer to how Notion renders dark-mode red text |
| Focus ring | `ring-foreground/10` + border brighten | No colored focus ring — stays monochrome |

`html { color-scheme: dark }` is set globally — this alone fixes native `<select>`/`<input type="date">` popups rendering as jarring white OS widgets on a dark UI.

## Shared class constants

Reusable Tailwind class strings live in `src/lib/ui.ts` (`fieldClass`, `btnPrimaryClass`, `btnGhostClass`, `btnPositiveClass`, `btnDestructiveClass`, `cardClass`, `numericClass`, `linkClass`) — plain exported strings, not a Tailwind `@layer components`/`@apply` setup, to avoid v4 `@apply`-chaining edge cases and keep everything in familiar JS. Use these instead of hand-typing a new ad hoc class string per input/button/card.

## Radius, motion, type

- Cards/modals: `rounded-2xl` (16px). Inputs/buttons: `rounded-lg` (8px).
- Motion is subtle (dial: 4/10) — 150–300ms transitions on hover/focus, a `fade-in-up` keyframe (`animate-fade-in-up` in `globals.css`) staggered per widget card on mount, `modal-in` (scale+fade) for the add-transaction modal. All animations respect `prefers-reduced-motion`.
- Text links (Edit / Delete / Customize / Cancel) use a soft dotted-underline treatment (`linkClass`) rather than solid underlines or full buttons — closer to how Notion treats secondary inline actions.
- A small `.fluxo` wordmark (accent-colored leading dot) appears consistently in the auth pages and the dashboard header for brand continuity.

## Pre-delivery checklist (kept from the skill's generic list, still applies)

- [ ] `cursor-pointer` on all clickable elements
- [ ] Hover/focus transitions 150–300ms, never instant
- [ ] Focus states visible for keyboard nav
- [ ] `prefers-reduced-motion` respected
- [ ] No emoji-as-icon (this app currently has no icon needs beyond text/symbols like "+" and "✕" — revisit if that changes)
- [ ] Responsive at 375/768/1024px — this app is phone-first (PWA), so 375px is the primary target, not an afterthought
